1. Introduction
===============

1.1. What Is This?

GImageView is an image viewer that runs on the X Window System, under
development to break through the hopeless situation of viewing huge numbers of
images (and movies).

This version (0.2.27+gtk4) is a port of GImageView 0.2.27 to GTK 4. It has
been tested on the X Window System (X11). On Wayland, embedded movie playback
with the MPlayer and xine plugins is not possible.

It is basically an image viewer, but since version 0.1.1 it also implements
simple file operations by drag and drop (image management functions). Since
0.2.3 it also supports movie playback using xine or MPlayer (the GTK 4 version
also supports GStreamer). The susie plugin, which was supported experimentally
in 0.2.3, has been removed in the GTK 4 version.

1.2. Features

GImageView has the following features.

 ・ Opening multiple directories at the same time, switching thumbnail views
    with tabs

 ・ Recursive loading of any directory; the root can be set

 ・ Low memory usage

 ・ Designed with careful consideration for use from the command line

 ・ Simple and flexible interface

 ・ Image management functions

 ・ Full slideshow support

 ・ Rich list view (supports multiple sort orders)

 ・ Image index: images by the date taken, by tags and automatic tags (folder
    name, camera, shape), searches by several conditions, saved searches (2.6,
    2.8)

 ・ Face recognition: images by the people in them, naming the faces (2.7)

 ・ File operations by drag and drop

 ・ Support for many thumbnail cache formats (all read and write)

     □ The freedesktop.org Thumbnail Managing Standard (~/.cache/thumbnails,
       shared with other programs)

     □ GImageView (its own format, ~/.gimv/thumbnail)

     □ Nautilus, Nautilus-2.0

     □ Konqueror (also the old format)

     □ GQview

     □ Electric Eyes (Picview)

     □ .xvpics

 ・ Supported image formats

     □ JPEG, PNG, BMP, PCX, TGA, MAG, XBM, XCF, xvpics (gimv's own loaders)

     □ PNM (PBM, PGM, PPM), XPM, Sun raster, WBMP, ZIM, Pi, PIC, MAKI (.mki),
       MB (PC-8801), MB2 (PC-9801), AK5/MSL (gimv's own loaders; added in the
       GTK 4 version. MAG, ZIM, Pi, PIC, MAKI, MB and MB2 are shown with the
       pixels of the screen of their machine: those of the PC-9801 and the
       like 1.2 high, of the 512 dots wide screens of the X68000 4/3 wide, of
       the 200 lines mode of MAG and MB2 and of MB twice as high again. The
       image size is the size stretched)

     □ SVG (librsvg), MNG (libmng), WMF (libwmf)

     □ Formats that gdk-pixbuf can read, such as GIF, TIFF and ICO

     □ WebP, AVIF, HEIF, JPEG XL, etc. (when the corresponding gdk-pixbuf
       loaders are installed)

     □ Animated GIF, MNG

    Files in formats for which no loader is available are not shown in the
    thumbnail list. The supported formats can be checked in "Plugin Info" in
    [Help | About].

 ・ Supported archive formats

     □ LZH (with liblhasa also the old methods (-lh1-, -lh4-, -lzs-, -lz5-,
       -pm1-, ...) and self-extracting archives (MS-DOS, X68000, ...); without
       it -lh1- of LHarc 1.x too)

     □ ZIP (CBZ)

     □ TAR (tar.gz, tar.bz2, tar.xz, tar.zst, etc.)

     □ RAR (CBR)

     □ 7z (CB7)

    Archives are expanded as virtual directories. In the GTK 4 version,
    archives are read with libarchive (external commands such as lha and unzip
    are not used).

 ・ Supported movie formats

     □ MPEG, AVI, QuickTime, WMV/ASF, MP4, Matroska (mkv), WebM, FLV, Ogg,
       MPEG-TS, 3GP, etc.

     □ MP3, WAV, Ogg, FLAC, AAC, etc. (audio)

    Playing movies and audio requires one of GStreamer, MPlayer or xine-lib.
    The formats that can actually be played depend on what each of them
    supports. For GStreamer, this depends on the installed plugins
    (gstreamer1.0-plugins-good, -bad, -ugly, gstreamer1.0-libav, etc.).

1.3. System Requirements

The following are required to compile and run this program.

 ・ GTK 4.12 or later : https://www.gtk.org/

 ・ GLib 2.72 or later, gdk-pixbuf 2.0

 ・ Meson and Ninja (build time only)

 ・ X Window System (X11) (the environment it has been tested on). On Wayland,
    embedded movie playback with the MPlayer and xine plugins is not possible.

In addition, the following libraries and programs, if present, extend the
functionality.

 ・ libarchive : Archives (zip, rar, 7z, lha, tar, etc.) can be opened.

 ・ liblhasa : Old LHA (lzh) archives are read with all their methods, and
    self-extracting archives are opened (used with libarchive).

 ・ libjpeg : JPEG images are loaded faster.

 ・ libexif : EXIF information can be displayed, and images (and thumbnails)
    can be rotated automatically according to the EXIF orientation
    information. Thumbnails of JPEG files are made faster from their embedded
    (EXIF) thumbnails.

 ・ gexiv2 (Exiv2) : with libexif, the EXIF information of the formats other
    than JPEG (TIFF, raw files, PNG, WebP, HEIF/AVIF, JPEG XL, ...) is
    displayed and used for the automatic rotation too. The index reads the
    date, the camera and the keywords (EXIF, XMP, IPTC) of these formats too.

 ・ SQLite 3.22 or later : the image index (dates, tags, search) can be used.

 ・ OpenCV 4.8 or later (and a C++ compiler) : faces can be found in the
    index. The model files (OpenCV YuNet and SFace) are needed too.

 ・ librsvg (2.52 or later) : SVG images can be displayed.

 ・ libmng : MNG animations can be played.

 ・ libwmf : WMF images can be displayed.

 ・ GStreamer 1.16 or later, xine-lib 1.2 or later, or MPlayer : Movie and
    audio files can be played.

 ・ Additional gdk-pixbuf loaders (webp-pixbuf-loader, libavif-gdk-pixbuf,
    heif-gdk-pixbuf, libjxl-gdk-pixbuf, etc.) : WebP, AVIF, HEIF, JPEG XL,
    etc. can be displayed.

The GTK 4 version has been tested on Debian (sid, GTK 4.24).

1.4. Getting GImageView

The original GImageView (up to 0.2.27) was published at the following
location. It is no longer updated.

 ・ https://github.com/ashie/gimageview

The GTK 4 version is a port based on 0.2.27.

1.5. Installation

The GTK 4 version is built with Meson. In the top directory of the source, do
the following.

  $ meson setup _build --prefix=/usr/local
  $ ninja -C _build
  $ sudo ninja -C _build install

Each feature is enabled automatically if the library is present. To specify
them explicitly, add options like the following to meson setup. See
meson_options.txt for the list of options.

  $ meson setup _build -Dgstreamer=enabled -Dxine=enabled -Dsvg=enabled -Dexif=enabled -Dmplayer=true

On Debian, you can also build a package and install it.

  $ dpkg-buildpackage -us -uc -b
  $ sudo apt install ../gimageview_*.deb

The configuration files (~/.gimv) of the GTK+ 2 version can be used as they
are. However, ~/.gimv/gtkrc is no longer used; instead, the appearance is
changed with ~/.gimv/gtk.css.

2. Usage
========

2.1. Command Line

Typing a command like the following lets you view image files.

  $ gimv [image files...]

Also, if you specify a directory name with the "-d" option as follows, all
image files in the directory are opened as thumbnails in the thumbnail window.

  $ gimv -d [directory]

If you specify image file names and directory names mixed together as follows,
image files are opened in the image window and directories in the thumbnail
window.

  $ gimv -d hoge01.jpg ~/ ~/images images/hoge02.jpg\
    /usr/share/pixmaps/ hogehoge.png ......

With the "-t" option, everything can be opened in the thumbnail window.

The other command line options are as follows.

  $ gimv -h

  Copyright (C) 2001 Takuro Ashie
  Usage: gimv [OPTION...] [Image Files...]

    -d, --directory          Scan a directory at startup
    -R, --recursive          Scan directories recursively (use with "-d")
    -D, --scan-dot           Read dotfiles when scanning directories (use with "-d")
    -e, --ignore-ext         Ignore file name extension
    -s, --scale=SCALE        Image scale in the image window [%]
    -b, --buffer=ON/OFF      Keep the original image in memory
    -M, --menubar            Show the menubar in the image window
    -T, --toolbar            Show the toolbar in the image window
    -I, --imagewin           Open an empty image window at startup
    -w, --thumbwin           Open the thumbnail window at startup
    -i, --imageview          Open all images in the image window
    -t, --thumbview          Open all images in the thumbnail window
    -S, --slideshow          Open the image files in a slideshow
    -W, --wait=TIME          Slideshow interval (use with "-S") [sec]
    -v, --version            Print version information
    -h, --help               Show this message

To open a directory from the GUI, double-click it in the directory view, or
type its path in the directory entry of the thumbnail window toolbar and press
Enter (a new tab is opened only if the directory has images). You can also
select directories in the file open dialog and press "Thumbnails of the
selected files".

2.2. Thumbnails

 ・ Thumbnails can be read and written in the format of the freedesktop.org
    Thumbnail Managing Standard (~/.cache/thumbnails), shared with other
    programs ([Preferences | Thumbnail Cache]).

 ・ The thumbnails of the images GdkPixbuf reads (JPEG, PNG, ...) are made in
    worker threads, so the window can be used while they are made. A JPEG's
    embedded (EXIF) thumbnail is used when it is big enough ("Making
    thumbnails" in [Preferences | Thumbnail Cache]).

 ・ Thumbnails are turned and flipped by the EXIF orientation, and kept so in
    the cache. When an image was turned or flipped in an image view (and that
    is remembered), its thumbnail is shown so (not kept in the cache).

2.3. Lists

Searching a list (Ctrl+F)
    Ctrl+F in a list (the directory view, the detail view, the Data tab, the
    lists of the preferences, ...) opens a search entry at its top. Type a
    name shown in the list (a file, a folder, a tag, ...): the first one
    beginning with it (else having it) is selected. Up and Down go to the one
    before and the next, Enter closes it on the one found, Escape closes it
    (and so do 5 seconds without typing). In the index tabs, the names inside
    the closed branches are looked at too. In the album modes of the thumbnail
    view too, Ctrl+F finds a thumbnail by its file name (chosen and scrolled
    to; Enter opens it). Elsewhere Ctrl+F is [File | Open...].

Status bar
    At the left, the full path of the focused image; in the middle, its
    position ("12 / 33") and its file size. With several images selected,
    their number and their total size ("5 selected 812 kB"). At the right end,
    the state of the index and the notices.

2.4. Comments (data, note and tags)

GImageView keeps the notes of each image (subject, date, location, ...) and
its tags in a separate text file, the comment file, without changing the image
file. "Comment" in this manual means what is in that file.

Comment files
    One file for each image, under ~/.gimv/comment, named the full path of the
    image with ".txt" (/home/user/Pictures/cat.jpg: ~/.gimv/comment/home/user/
    Pictures/cat.jpg.txt). In it are lines "key: value" (the data), then free
    text (the note). The character set is chosen in [Preferences | Comment].
    An image without a comment has no file.

What is kept in it
    The values of the "Data" tab (subject, date, location, ...: more keys can
    be added in [Preferences | Comment]), the text of the "Note" tab, the tags
    added by hand with "Edit Tags..." (the X-IMG-Tags line), the names given
    to the faces (the tags "person/NAME") and the rotation and flip of each
    image (not shown in the comment editor). The automatic tags of the index
    and the comments, EXIF and keywords inside the image files are not written
    in it.

Seeing and editing
    The comment window is opened from the right button menu of the thumbnails
    or [Edit | Edit Comment...] of the image window. The "Data" tab of the
    preview shows the same. The detail view ("Subject" and "Comment" columns)
    and the tooltips of the album view can show it too.

The "Data" tab
     ・ The "Data" tab of the preview and of the comment window shows the
        comments written in the image file itself (JPEG, PNG, GIF, MAG, MAKI,
        Pi, PIC, MB2, AK5/MSL) in italics (shown only); the list shows their
        first 4 lines and how many more (the whole text pops up under the
        mouse), and the one selected is shown whole, with its lines, in place
        of the value; for an image in an archive they are read from the file
        extracted for the preview.

     ・ For a song or a movie, the information in the file (title, artist,
        album, track, genre, length, the formats of the sound and the picture,
        ...) is shown in the "Data" tab too, in italics (shown only; the
        GStreamer plugin).

     ・ In the "Data" tab, choose a "Key", type the "Value" and press Enter or
        "Save" (the value is free text; a date in "Date" is the date of the
        image for the index).

     ・ "Remove Item" of the "Data" tab (Delete in the list) removes the item
        selected, kept by "Save". "Delete Comment..." below deletes, after
        asking, the data and the note of the image; the tags (X-IMG-Tags) are
        kept. The row of the tags is only shown: the tags are edited with
        "Edit Tags...".

Moving images, the index
    Images moved, copied or renamed by GImageView take their comment files
    with them. Images moved by other programs and lost can be given their
    comments back in [Tools | Missing Images...]. The comment files are apart
    from the database of the index: the tags and names are kept when the index
    is made again.

2.5. Bookmarks

Images can be bookmarked to look at them again later, in the indexed
directories or not. The bookmarks are kept in ~/.gimv/bookmarks (apart from
the index database: making the index again keeps them).

Bookmarking
    Select images in the thumbnail view (one or more) and choose [Edit |
    Bookmark...] or "Bookmark..." in the right button menu; in the image
    window [Edit | Bookmark...], in the preview "Bookmark..." in the right
    button menu. The images are bookmarked at once, and a field for a note
    comes up. It can be closed with Escape without writing anything (a note
    can be written later). Enter, or a click elsewhere, keeps the note
    written. Chosen on a bookmarked image, it changes the note, or "Remove"
    takes the bookmark off.

Key
    No key is given by default. One can be given in [Edit | Keyboard
    Shortcuts...]. With lines like these in ~/.gimv/keyaccelrc (Ctrl+K here; a
    line starting with ";" does nothing), the key bookmarks from the next
    start.

      (gtk_accel_path "<ThumbWinMainMenu>/Edit/Bookmark..." "<Control>k")
      (gtk_accel_path "<ImageWinMainMenu>/Edit/Bookmark..." "<Control>k")
      (gtk_accel_path "<ThumbWinPreviewPop>/Bookmark..." "<Control>k")

Bookmarks tab
    The "Bookmarks" tab (a star) next to the directory view lists the
    bookmarks by the day they were added (Today, Yesterday, This Week, then by
    month), and "All", "With a Note", "Without a Note", with their numbers. A
    click on a row opens them in the result tab, the newest first (the file
    names only, as the index tabs). Choosing a sort in the menu sorts them so.

The notes
    The tooltip of the thumbnail of a bookmarked image starts with "★ the
    note" ("★ Bookmarked" without a note).

Moved and missing images
    An image renamed or moved with GImageView keeps its bookmark. In the
    indexed directories, the bookmarks also follow images and folders moved or
    renamed by other programs. Other images not found any more are counted in
    "Not Found" of the tab.

2.6. Image index (dates and tags)

When "Directories to index" are given in [Preferences | Index], an indexer
process (gimv-indexer) looks at the images below them while GImageView runs,
and keeps their dates and tags in a database (~/.local/share/gimageview/
index.db). The indexer runs at a low priority, and also takes in files added,
moved and deleted while GImageView runs. Its progress is shown at the right
end of the status bar ("Index: ..."). This needs a build with SQLite.

With an index, the side notebook of the thumbnail window (where the directory
view is) gets the "Date" and "Tag" tabs (and "People" when faces can be
found).

Date tab
    The images by the date they were taken, in years, months and days, newest
    first, with their numbers. The date is the date written in the "Date" of
    the comment ("2025-04-01", "2025/4/1 10:15", "2025年4月1日 10時15分", ...;
    for images of SNS, whose EXIF is removed and whose names are not dates),
    else the EXIF date (built with gexiv2, the XMP date too), else a date in
    the file name, else the modification time. A click on a row opens the
    images of the day (month, year) in the result tab, newest first. The
    detail view shows the arrow on "Date taken". Choosing a sort in [View |
    Sort File List] or a title of the detail view sorts them so (the one
    already chosen too).

Tag tab
    The tags put by hand at the top, then "Names of People" and the groups of
    the tags put automatically (in blue: Folders, Cameras, Shape, Tags of
    People). The keywords other programs put are shown with the tags put by
    hand, one row for a name (a click opens the images with either; renaming
    and merging are for the tags put by hand, the keywords are changed in the
    program that put them).

    A "/" in a tag makes a tree: "Travel/Kyoto/Temple" is shown as "Temple"
    below "Kyoto" below "Travel" (the hierarchical keywords of other programs
    too). A parent counts the images of the tags below it too, and a click on
    it opens them all; a parent is shown even when it is not put on an image
    itself. Renaming (F2) edits the whole name ("Travel/Kyoto"), and the tags
    below a parent renamed change with it ("Travel" to "Trips" makes "Trips/
    Kyoto"); changing what is before a "/" moves a tag below another parent. A
    tag put by hand can be dragged in the tag tab and dropped on another tag,
    to choose "Move Below "Travel" (Travel/Cat)" or "Merge Into "Travel"" (the
    tags below it go with it); dropped on the "Tag" row or below the rows, it
    can be moved to the top. Merging, or a tag of the same name where it goes,
    is asked about first. Automatic tags, tags that are only keywords and the
    names of people cannot be dragged. A tag given in the search window takes
    the images of the tags below it too.

Opening
    A click on the text of a row shows its images in the result tab of the
    thumbnail view (one tab, whose contents are replaced). The middle button,
    or "Open in New Tab" of the right button menu, opens a new tab. Moving
    with the arrow keys opens nothing; Enter does. A result tab shows the file
    names only; the full path is in the tooltip and the status bar. "Open the
    Folder" of the right button menu opens the folder of the image. With tens
    of thousands of images, only the thumbnails near the part shown are made.

Tagging
    "Edit Tags..." of the right button menu of the thumbnail view, or [Edit |
    Edit Tags...], tags the images selected (one or more); in the image window
    [Edit | Edit Tags...] or the right button menu of the image, in the
    preview "Edit Tags..." in the right button menu, tags the image shown. A
    tag typed in the entry at the top is put on with Enter (several separated
    by commas; a tag may have "/" in it, like "travel/Kyoto"). The tags on the
    images are shown below it, × takes one away. "Tags in Use" at the bottom
    lists the tags most used first, narrowed by what is typed; a click puts
    one on. The parents of a tag with levels are dimmed, like "travel/Kyoto".
    A click on a parent in a row of "Tags in Use" ("travel") makes the entry
    "travel/" and leaves only the tags below "travel" in the list: type the
    name of the child after it, or pick one. When what is typed has "/" in it,
    only the tags beginning with it are listed. With several images, a tag
    only some of them have is shown as "Kyoto 2/5": a click puts it on all of
    them, × takes it away from all of them (left alone, it stays as it is on
    each). Enter with nothing typed is OK.

    "Edit Tags with the Folders in It..." of the right button menu of a folder
    in the directory view edits the tags of all the images in the folder and
    in the folders in it (without opening or selecting them). The images are
    looked for in the background, their number shown when it takes a while (it
    can be cancelled). The dialog is the same. With many images the writing
    shows its progress, and "Stop" stops it: the images done so far are
    changed, the others are as they were. Every image is checked before
    anything is written, so nothing is written when the tags of one would be
    too long.

    They are written in the "X-IMG-Tags:" line of the comment files (~/.gimv/
    comment, 2.4), so they are kept when the index is made again. The names of
    the people given to the faces (the tags "person/NAME") are not among the
    tags: they are shown under "People" and kept as they are (names are given
    in the faces window or the faces panel). The "Tags:" row of the "Data" tab
    (comment window and preview) shows the tags of the image; a click opens
    the images with the tag. A tag with levels is shown part by part, like
    "travel / Kyoto / temple": a click on a parent part (dimmed) opens the
    images with it and with the tags below it.

Renaming and merging tags
    Select a tag put by hand (or a tag of people) in the Tag tab and press F2,
    or choose "Rename... (F2)" in the right button menu. When the new name is
    there already, you are asked whether to merge them. The comment files are
    rewritten in the background. Ctrl+C copies the name of a row.

Automatic tags
    The index tags the images with their folder name, their camera (EXIF),
    their shape (portrait, landscape, square) and the keywords other programs
    put ([Preferences | Index | Automatic Tags]). The keywords are read from
    the XMP in the image (dc:subject), the IPTC keywords, and the sidecar
    files next to the image ("name.jpg.xmp" of digiKam, darktable, ... and
    "name.xmp" of Lightroom, ...). When there are only keywords with levels
    ("Season|Spring"), the last part is used. A sidecar file written again
    makes the index read the keywords of its image again. A keyword with the
    name of a tag put by hand is shown and looked for as that tag (the Tag
    tab, the Data tab, the search window, "Tags in Use" of Edit Tags). Built
    with gexiv2 (Exiv2), the date, the camera and the keywords are read from
    every format Exiv2 knows (JPEG, HEIF, PNG, WebP, TIFF, raw files, ...);
    without it, the EXIF of JPEG only and the XMP of JPEG, PNG, WebP and TIFF
    only. Folder names of numbers only and DCIM are not made tags. Other
    folder names can be added to "Folder Names Not Made Tags" ("*" and "?" can
    be used), or with "Do Not Make This Folder Name a Tag" in the right button
    menu of a folder in the Tag tab (not while the preferences window is
    open). The automatic tags are kept in the index only, not in the comment
    files.

New images and notices
    New images in the indexed directories are notified on the desktop (the
    time to gather them, the interval and the folders not to notify are in
    [Preferences | Index | New Images]). The "Notices" button of the status
    bar shows the number of new images since the last time, and asks things
    such as whether to move the comments of images another program moved.

Missing images
    Images with comments (tags) that went missing are listed in a log for each
    start (~/.local/share/gimageview/missing-*.log). In [Tools | Missing
    Images...] their comments can be put on where the image went, put on
    another image, deleted, or the lines removed from the log.

2.7. Faces and people

gimv-faces looks for faces in the images of the "Folders to find faces in" of
[Preferences | Index | Faces] (which must be in the index), and puts faces
that look alike in groups. It runs after the rest of the index, slowly. This
needs a build with OpenCV 4.8 or later, and the model files (OpenCV YuNet and
SFace, about 40 MB) in ~/.local/share/gimageview/models (their names and where
to get them: [Preferences | Index | Faces]; the preferences page shows them
too).

People tab
    The people named (grouped by their tags), the guesses ("name?"), the
    unnamed groups, the other faces and the ignored faces. A click opens the
    images of the person; "Show the Faces..." of the right button menu opens
    the faces window (the right button menu: 6.3.4).

Faces window
    The people (also the unnamed groups and the guesses) are listed at the
    left with a face and their name, and the faces of the one selected at the
    right. Select faces (Ctrl+A: all of them) and choose "Name...", "Right",
    "Not This Person", "Remove the Name" or "Ignore". A double click opens the
    image. The buttons of the heading rename the person (merging two people of
    the same name), copy the name, edit the tags of the person and delete the
    person. The faces can be sorted oldest first, newest first, or least like
    the person first (to find the faces put there by mistake).

Faces panel
    "Edit Faces (People)" (P) in the right button menu of an image view shows
    the faces of the image at its right, where they can be named too. Press
    "+" and drag over the image to add a face that was not found (a small
    face, for example). The right button menu of a face copies it to the
    clipboard.

Names and the comment files
    The names given to the faces are written in the comment files of the
    images too, as the tags "person/NAME"; when the index is made again, the
    names are given back to the faces from them. The "Names of People" group
    of the Tag tab shows these tags.

Tags of people
    Tags put on people (the group they belong to, for example), with "Tags of
    the Person..." in the faces window. They are kept in the index only, and
    used by the "Tags of People" group of the Tag tab and the groups of the
    People tab. Renaming one renames it for everyone who has it.

    As the tags put by hand, they make a tree by "/": "Family/Parents" is a
    tag below "Family". The "Tags of People" group of the Tag tab, the People
    tab and the search window show them as a tree; a parent (shown even when
    no person has it itself) counts the images of the people of the tags below
    it too, and choosing a parent shows those people as well. The Data tab
    shows "People: Family / Parents" part by part, a parent part opening the
    images of the parent. Renaming a parent renames the tags below it. In the
    Tag tab a tag of people can be dragged onto another tag of people, to move
    it below that tag or to merge it into it (onto the "Tags of People" row:
    to the top). The "Tags of the Person..." dialog dims the parents, and a
    click on a parent of a tag other people have types "Family/" in the entry,
    leaving only the tags below it in the list.

2.8. Searching images

[Tools | Search Images...] finds images of the index by several conditions.

 ・ A click on a tag of the list below (names of people and automatic tags
    too) adds it as a condition, shown as a chip at the top. Typing in the
    entry narrows the list; Enter adds the first tag. The images must have all
    the chips (and). A click on a chip turns it into "excluded" (red): the
    images with that tag are left out. × removes a chip.

 ・ "Taken from ... to" limits the date taken (a year or a month alone can be
    given).

 ・ With conditions, the list below shows the tags of the images found, by
    kind and with their numbers: a click narrows the search further, and the
    "exclude" button of a row leaves those images out.

 ・ Tags with "/", like "Travel/Kyoto", make a tree as in the Tag tab. A
    parent counts the images of the tags below it too (a parent is shown even
    when it is not put on an image itself), and its ▸ shows the tags below it.
    A click on a parent narrows the search to the images with it or a tag
    below it. With a parent as a condition, the tags below it ("Travel/Kyoto")
    come to the top level of the list, to narrow further. Typing shows the
    tags whose last part ("Temple") has the text, with their parents open
    (with "/" typed, the whole name is looked at).

 ・ The images found are shown in a tab of the thumbnail window.

 ・ "Keep..." keeps the conditions under a name, to be chosen again in the
    list at the top (~/.gimv/searches); the trash button deletes one.

2.9. Other features

 ・ "Copy the Image to the Clipboard" (Shift+Ctrl+C) in the right button menu
    of an image view copies the image shown, to be pasted in other programs.

 ・ "Flip Horizontally" (X) and the rotation of the image in an image view are
    remembered for each image and restored when it is opened again ("Remember
    the rotation and flip of each image" in [Preferences | Image Window |
    Image]).

 ・ "Open the Folder" in the right button menus of the thumbnail view and the
    image view opens the folder of the image.

3. What Do You Want to Do?
==========================

This chapter finds the way to do things from what you want to do. Each gives
the outline only; see the links for more. The index and face features need a
build with them.

3.1. Getting the index ready

I want to find my images by date and tag
    Add the folders of your pictures to "Directories to index" in [Preferences
    | Index]. The index is made while GImageView runs, and the "Date" and
    "Tag" tabs appear next to the directory view. The progress is shown at the
    right end of the status bar. This needs a build with SQLite.

    See 2.6. Image index, [Preferences | Index].

I want to find my images by the people in them
    Give the "Folders to find faces in" in [Preferences | Index | Faces] and
    put the model files in place. Faces are looked for after the index, and
    the "People" tab shows the faces that look alike in groups. This needs a
    build with OpenCV.

    See 2.7. Faces and people, [Preferences | Index | Faces].

3.2. Tagging and arranging tags

I want to tag several images at once
    Select the images in the thumbnail view: Ctrl+click adds one (or takes it
    away again), Shift+click selects all between, and a drag starting where
    there is no image selects the images in the rectangle; Ctrl+A selects all.
    Then choose "Edit Tags..." in the right button menu or [Edit | Edit
    Tags...], type a tag and press Enter; Enter with nothing typed is OK. The
    number selected is shown in the status bar ("5 selected").

    See Tagging, Select All.

I want to tag all the images of a folder (and the folders in it)
    Right-click the folder in the directory view and choose "Edit Tags with
    the Folders in It...". The folder need not be opened, nor the images
    selected. With many images the progress is shown, and "Stop" stops it.

    See Tagging, the right button menu of the directory view.

I want to take a tag off several images
    Select the images and open "Edit Tags...": a tag put on some of them only
    is shown as "Kyoto 2/5". × takes it off all of them, a click puts it on
    all of them; left alone, each image keeps what it has.

    See Tagging.

I want to rename a tag, or merge two tags
    Select the tag in the Tag tab and press F2, or choose "Rename..." in the
    right button menu. Giving a name that is there already asks whether to
    merge them. A tag dragged onto another one in the Tag tab can be merged
    too.

    See Renaming and merging tags.

I want to arrange tags in a tree ("Travel/Kyoto")
    A "/" in the name of a tag makes a tree. Drag a tag in the Tag tab onto
    the tag to be its parent and choose to move it below that tag. A click on
    a parent opens the images of the tags below it too.

    See Tag tab.

3.3. Finding images

I want to see the images with a tag
    Click the text of the row in the Tag tab: the images are shown in the
    result tab. The middle button opens a new tab. A tag in the "Data" tab of
    the comment window or the preview opens them too.

    See Opening.

I want to find images by the day they were taken
    Open the year, month and day in the Date tab and click it. For an image
    whose date is not known (an image of SNS, for example), a date written in
    the "Date" of the "Data" tab is used as its date.

    See Date tab, 2.9. Other features.

I want to combine conditions ("Kyoto" without "Cat", for example)
    [Tools | Search Images...] combines tags, people and the dates taken. A
    click on a tag adds it as a condition, and a click on the chip of a
    condition turns it into "excluded". Conditions used often can be kept
    under a name with "Keep...".

    See 2.8. Searching images.

I want to open the folder of an image found
    "Open the Folder" in the right button menu of the thumbnail view or the
    image view. A result tab shows the file names only; the full path is in
    the tooltip and the status bar.

    See Opening.

3.4. People

I want the images of one person
    Click the person (or an unnamed group) in the People tab. "Show the
    Faces..." of the right button menu opens the faces window to look at the
    faces.

    See People tab.

I want to name faces, or take wrong faces away
    Select faces in the faces window (Ctrl+A: all of them) and choose
    "Name...", "Not This Person", ... Sorting them "least like the person
    first" brings the wrong faces to the top. For one image, "Edit Faces
    (People)" (P) in the right button menu of the image view names them too.

    See Faces window, Faces panel.

I want to add a face that was not found
    Show the faces panel with "Edit Faces (People)" (P) in the right button
    menu of the image view, press "+" and drag over the face in the image.

    See Faces panel.

3.5. Keeping images in order

I want to find duplicate images and clear them away
    The same files in different folders: [Tools | Find Duplicates in the
    Index...] looks among all the indexed images (below a folder: the right
    button menu of the directory view; the same files as an image: "Find the
    Same Files" of the thumbnail view). Other sizes and similar pictures: open
    the images in a tab and choose [Tools | Find Duplicates...]. Check "Keep"
    and "Delete" and move them to the trash group by group (they can be
    restored from the trash), or all at once with "Move All Marked to
    Trash...". To keep the file names, "Trash and Leave Links" in the
    confirmation leaves a link to the image kept under each name.

    See Find Duplicates in the Index..., Find Duplicates....

I want to put the tags and comments of a moved image back
    Images moved with GImageView take their tags and comments with them.
    Images moved by other programs and not found any more are listed in [Tools
    | Missing Images...], where their comments can be put on where they went.

    See Missing images.

I want to mark images to look at them again later
    Select the images and choose "Bookmark..." in the right button menu; a
    note can be written. The "Bookmarks" tab (a star) next to the directory
    view opens them by the day they were bookmarked.

    See 2.5. Bookmarks.

I want to add a note to a bookmark later
    Click "Without a Note" in the Bookmarks tab (the star): the images without
    a note are shown in the result tab. Select one and choose "Bookmark..." of
    the right button menu (or [Edit | Bookmark...]) again: the field of the
    note comes. Write it and press Enter (what is written is kept too when the
    field is closed by a click elsewhere or Escape). A note there already is
    in the field, to be written again.

    With several images selected, the note written goes to all of them (their
    notes before are replaced; closed with nothing written, each keeps its
    own).

    See 2.5. Bookmarks, 6.3.5. The Bookmarks tab.

I want to save an image in another format (HEIC as JPEG, ...)
    [File | Save Image...] (Ctrl+S) of the image window, or "Save Image..." in
    the right button menu of the preview, saves it in the format and quality
    chosen.

    See Save Image....

I want to make photos smaller to save space
    Select the images in the thumbnails and choose "Save Smaller..." in the
    right button menu. It saves them shrunk, for example to 800 px of height
    or less, as new files (the originals stay as they are). It can also leave
    out the location information.

    See Save Smaller....

I want to join some images into one (a photo taken in pieces, ...)
    Select them in the thumbnails and choose "Join Images..." in the right
    button menu: they are put one below another, side by side or in a grid and
    saved as a new file. When they are pieces of one photo that overlap, the
    overlaps are found and can be put right by hand.

    See Join Images....

I want to take off the background around a scanned image
    Show the image and press C (or "Crop Image..." in the right button menu),
    then "Detect the Edges" chooses what is inside the background around it (a
    border of one color, white, black, ...). Put the frame right by hand if
    needed and press Enter: it is saved as "name_crop.jpg" (the image stays as
    it is). Any part can be cropped by dragging the frame too.

    See Crop Image....

3.6. Making it yours

I want to read a comic two pages at a time
    Open the folder or the archive (zip, cbz, rar, lzh, ...), choose the first
    page and turn on [Two Pages | Two Pages] of the right button menu of the
    preview, or press T. Turn the pages with a click (the left half on, the
    right half back) or Space. When the pages do not pair, O shifts them by
    one. To show four pages at a time or in another layout, choose it from
    [Two Pages | Page Layout] ([Two Pages | Edit Layouts...] adds more).

    See Two Pages.

I want to change the keyboard shortcuts
    [Edit | Keyboard Shortcuts...]: click the key of a row and press the new
    key. The entry at the top narrows the list by name or key.

    See Keyboard Shortcuts....

I want to find a name in a long list
    Press Ctrl+F in the directory view, the Tag tab, the detail view, ... and
    type the name.

    See Searching a list.

4. Menu Bar
===========

This section describes the items of the menu bar. Both the thumbnail window
and the image window have a menu bar; they are described together here. Items
that exist in only one of the windows are marked "Thumbnail window only" or
"Image window only". The keys in [ ] after an item are its default shortcut
keys.

4.1. File

Open... [Ctrl + F]
    Shows the file open dialog.

    "Open selected files" creates a new image window and shows the images.

    "Thumbnails of the selected files" creates a new collection tab and shows
    the files there as thumbnails (a collection). Selected folders
    (directories) are opened in a new tab each (as with a double click in the
    directory view). If files and folders are selected together, the files go
    to the collection tab and each folder to its own tab.

New Image Window [Ctrl + I]
    Creates a new, empty image window.

New Window [Ctrl + W]
    Thumbnail window only. Creates a new thumbnail window.

New Thumbnail Window [Ctrl + W]
    Image window only. Creates a new thumbnail window.

New Tab [Ctrl + T]
    Thumbnail window only. Creates a new, empty tab.

Memory Buffer [Ctrl + B]
    Image window only. Keeps the image shown in the memory buffer. For details
    see "Making the image view draw faster" in the Tips.

Save Image... [Ctrl + S]
    Image window only. Saves the image shown to another file in the format
    chosen (a HEIC as a JPEG, ...). "Save Image As..." of the mouse menu of
    the preview in the thumbnail window does the same.

     ・ Save to: at first the folder and the name of the image, with the
        extension of the format ("_2" is added to the name when it would be
        the image itself). "Browse..." chooses it in a file dialog. When the
        file is there already, it asks before overwriting it.

     ・ Format: those of JPEG, PNG, WebP, AVIF, TIFF, BMP and PNM that can be
        saved (WebP, AVIF, ... when gdk-pixbuf can write them).

     ・ Quality: of JPEG, WebP and AVIF (1 to 100, 90 by default).

     ・ Keep the information of the file (EXIF, XMP, IPTC): when built with
        gexiv2 (Exiv2). The information of the file is copied to the new file
        (JPEG, PNG, WebP, TIFF). The image is saved turned as it is shown, so
        the orientation of the information is put to normal, and the thumbnail
        of the EXIF is left out.

    The image is saved in its full size, turned (rotated, mirrored) as it is
    shown. It is written in another thread. A thumbnail window showing the
    folder saved to is refreshed. The format and the quality chosen are
    remembered until gimv quits.

Print... [Ctrl + P]
    In the thumbnail window, prints the images selected in the thumbnail view,
    one image per page. When no image is selected and the preview shows an
    image, that image is printed.

    In the image window, prints the image shown, in the orientation it is
    rotated to.

Close Tab [Q]
    Thumbnail window only. Closes the active tab.

Close Window [Ctrl + Q] / Close [Q]
    "Close Window" of the thumbnail window closes the thumbnail window; image
    windows that are open stay open. "Close" of the image window closes that
    image window.

Quit [Ctrl + C]
    Closes all windows of GImageView.

    All thumbnail windows and image windows are closed.

4.2. Edit

Select All [Ctrl + A]
    Thumbnail window only. Selects all files of the active tab.

Unselect All [Ctrl + N]
    Thumbnail window only. Unselects the files of the active tab.

    GImageView keeps the selection of each tab. "Unselect All" does not
    unselect the files of tabs that are not active.

Refresh List [Shift + Ctrl + R]
    Thumbnail window only. Refreshes the list of the active tab.

Reload Cache [Shift + R]
    Thumbnail window only. Reloads the cache of the active tab.

Update All Thumbnails [Ctrl + R]
    Thumbnail window only. Creates the thumbnails of the active tab again. The
    part on screen is made first and the rest in the background, keeping the
    scroll position. The progress (n/N) is shown while it runs, and the stop
    button in the toolbar stops it.

    For the differences between "Refresh List", "Reload Cache" and "Update All
    Thumbnails", see "The difference between Refresh List, Reload Cache and
    Update All Thumbnails" in the Tips.

Rename... [Shift + E]
    Thumbnail window only. Renames the image (file) selected in the thumbnail
    view.

    The name without the extension is edited; the extension (.jpg, ...) stays
    (without it the file is no longer shown as an image). "Change the
    extension too" edits the whole name; a new name without the extension of
    an image is then asked about, and [Rename without It] renames it so.

    It cannot be used when more than one file is selected.

File Names to UTF-8...
    Folder tabs of the thumbnail window only. Renames the files whose names
    are not in UTF-8 (given in Shift_JIS in the MS-DOS days or in EUC-JP on
    UNIX; in the list they are shown in italics or as %XX, 7.1.2) to UTF-8,
    all at once.

    For each file the bytes of its name now, the charset (the one guessed;
    Shift_JIS, EUC-JP, ISO-2022-JP or ISO-8859-1 can be chosen) and the new
    name are shown. Check the new names and press [Rename N Files]. A file
    whose new name is taken already, that would get the name of another file
    or that cannot be read in the charset is not renamed (nothing is
    overwritten). The thumbnail cache, the comment and the bookmark go with
    the file.

Copy Files To... [Shift + C]
    Thumbnail window only. Copies the selected images (files) to another
    directory.

    Tab completion can be used in the dialog that selects the directory.

Move Files To... [Shift + M]
    Thumbnail window only. Moves the selected images (files) to another
    directory.

    Tab completion can be used in the dialog that selects the directory.

Link Files To... [Shift + L]
    Thumbnail window only. Creates symbolic links to the selected images
    (files). Specify the directory to create the links in.

Remove Files... [Delete]
    Thumbnail window only. Deletes the selected images (files).

    This cannot be undone. Answer the confirmation dialog carefully.

Edit Comment...
    Image window only. Edits the comment of the image shown (the data,
    subject, date, ..., and the note, kept in a comment file apart from the
    image file: 2.4).

Show EXIF Data...
    Image window only. Shows the EXIF data of the image shown; built with
    gexiv2 (Exiv2), of the formats other than JPEG too.

Create Thumbnail [Shift + T]
    Image window only. Creates the thumbnail of the image shown, in the format
    of "Cache type for saving" in [Preferences | Thumbnail Cache].

Crop Image... [C]
    Image window only. Crops the image shown and saves the part as a new file;
    the image is not changed. "Crop Image..." in the right button menu of the
    image view and of the preview is the same.

    A frame of the part (the whole image at first) is shown on the image, and
    a bar above it; outside the frame the image is darker.

     ・ Dragged inside, the frame moves; dragged at a side or a corner (the
        white squares), its size changes; dragged outside it (or anywhere
        while it is the whole image), a new frame is drawn. Dragging outside
        the image scrolls as before.

     ・ Detect the Edges: the frame takes what is inside the border of the
        color of the edges of the image: for a small thing scanned on a sheet
        of A4 or taken on a black cloth: one color (white, black, ...) around
        it. The shadows of the edges of the scanner and dust are left out, a
        small margin is kept. The result is the frame, to be put right by hand
        before saving.

     ・ Settings (≡): the color tolerance (40 by default: larger for a noisy
        scan, smaller for a pale thing), the margin (px, 8 by default), the
        quality (JPEG, WebP; 90 by default), keeping the information of the
        file (EXIF, ...), copying the comment and the tags given by hand.

     ・ Ratio: free, the one of the image, 1:1, 4:3, 3:2, 16:9; standing or
        lying as the frame does.

     ・ The size of the frame is shown in pixels of the image.

     ・ Save [Enter]: saved next to the image as "name_crop.jpg" (in the
        format of the image; JPEG when gdk-pixbuf cannot write it, PNG with
        transparency or for the formats of gimv's own loaders, MAG, Pi, ...; a
        PNG takes the comments written in the image). When the name is taken,
        -1, -2, ... is added: nothing is overwritten. A "Show" button then
        chooses the new image in the thumbnail window.

     ・ Stop [Esc]: stops cropping; going to another image or turning it stops
        it too.

    The image is cropped in its full size, turned as it is shown (rotation,
    flip). It is read, its edges found and the part saved in threads.

Edit Tags...
    Only with the image index. Edits the tags of the selected images (in the
    image window, the image shown) (2.6). No key by default.

Bookmark...
    Bookmarks the selected images (in the image window, the image shown) and
    shows a field for a note (2.5). No key by default.

Options... [Ctrl + O]
    Shows the preferences dialog.

    See 7 for the settings.

Keyboard Shortcuts...
    Shows the keys of the menu items of the thumbnail window (with the
    preview) and the image window, and the other keys (the right button menu,
    completing a path, the navigator, the display modes of the thumbnail
    window), to change them. Click the key of a row and press the new key:
    Escape leaves it as it was, Backspace leaves the item without a key. When
    the key is the key of another item of the same window, you are asked
    whether to take it away from that item. The undo button of a row, or
    "Reset All to Defaults...", brings back the default. A key changed works
    at once (the keys of the display modes from the next start) and is written
    in ~/.gimv/keyaccelrc or ~/.gimv/keyconf. The entry at the top narrows the
    rows by a part of the name or of the key ("ctrl+t").

4.3. View

Sort File List
    Thumbnail window only. Sorts the thumbnail view in the order chosen.

    The order applies to the active tab and to all tabs opened afterwards.

    Like the selection, GImageView keeps the order of each tab, so tabs that
    are not open keep their order. These orders can be chosen:

     ・ by Name

     ・ by Access Time

     ・ by Date Taken (the date of the image index: the "Date" of the comment,
        EXIF, a date in the file name, the modification time, in this order;
        the modification time for an image outside the index. "Reverse Order"
        puts the newest first)

     ・ by Change Time

     ・ by Size

     ・ by Type

     ・ by Image Width

     ・ by Image Height

     ・ by Image Area

    "Reverse Order", "Case Insensitive", "Mix Directories and Files" and
    "Numbers by Value" can be set as well.

    With "Numbers by Value" (on by default) the numbers in names are compared
    as numbers, not as characters: 0p.jpg, 1.jpg, 2.jpg, 10.jpg, and not
    10.jpg before 2.jpg or 0p.jpg after 09.jpg. Of the same value the one with
    fewer zeros comes first (1.jpg, 01.jpg).

Layout
    Thumbnail window only. Changes the layout of the views (directory,
    thumbnail and preview) of the thumbnail window: Layout 0 to 4 (Ctrl + 0 to
    4) or Custom. For the custom layout, see "About the custom layout" in the
    Tips.

    In the GTK 4 version the layouts are shown as a row of buttons with
    pictures of the arrangement. In the pictures, D is the directory view, T
    the thumbnail view and P the preview. The tooltip of a button shows the
    name and the shortcut key (Ctrl + 0 to 4). The picture of Custom shows the
    current custom layout.

Layout | Window Composition
    Thumbnail window only. Chooses the arrangement of the views (directory,
    thumbnail and preview) of the thumbnail window from the prepared
    compositions.

    In the GTK 4 version the compositions are shown as buttons with pictures
    of the arrangement. The tooltip of a button shows its name.

Slideshow [Ctrl + S]
    Thumbnail window only. Starts a slideshow of the active tab.

    The slideshow is set up in 7.5.

Slideshow Options
    Thumbnail window only. The order and the files of the slideshow.

     ・ Start from the First / Start from the Selected / Random Order: the
        order.

     ・ Selected Only: shows only the selected images.

     ・ Images and Movies / Images Only / Movies Only: the kinds of files
        shown.

Zoom
    Image window only. Zooms (enlarges or reduces) the image shown and sets
    "Keep Aspect Ratio".

    There are Zoom In [S], Zoom Out [A], Fit to Window [W], Fit Width [Shift +
    W], Fit Height [Shift + H], Keep Aspect Ratio [Shift + A], and 10% to 200%
    [1 to 9]. For other scales use the toolbar.

    When "Keep Aspect Ratio" is checked, the aspect ratio of the image is kept
    when it is enlarged or reduced.

Rotate
    Image window only. Rotates the image shown (the image file is not
    changed): Rotate 90 Degrees Clockwise [R], Rotate 90 Degrees
    Counterclockwise [E], Rotate 180 Degrees [D], and Flip Horizontally [X].
    The rotation and the flip are remembered for each image and shown again
    when it is opened (Remember the rotation and flip of each image).

Ignore Alpha Channel
    Image window only. Shows the image without its transparency.

Checkerboard Behind Transparency
    Image window only. The background of images with transparency is shown as
    a gray checkerboard. The initial state follows Show a checkerboard behind
    transparent parts of images in [Preferences | Image Window].

Directory View [Shift + D]
    Thumbnail window only. Shows or hides the directory view.

Preview [Shift + P]
    Thumbnail window only. Shows or hides the preview.

Menubar [M]
    Shows or hides the menu bar.

Toolbar [N]
    Shows or hides the toolbar.

DirView Toolbar [Shift + N]
    Thumbnail window only. Shows or hides the toolbar of the directory view.

Slideshow Player [Shift + N]
    Image window only. Shows or hides the toolbar for controlling slideshows.

Statusbar [V]
    Shows or hides the status bar.

Scrollbar [Shift + S]
    Image window only. Shows or hides the scroll bars.

Tab [B]
    Thumbnail window only. Shows or hides the tabs of the thumbnail view.

Tab (Preview) [Shift + Z]
    Thumbnail window only. Shows or hides the tabs of the preview.

Player
    How the toolbar for playing movies and audio is shown: "Show", "Hide" or
    "Auto". "Auto" shows it only while a movie or audio file is shown.

Two Pages
    Shows pages side by side like a book or a comic (the preview and the image
    window; in the preview from the right button menu). Two pages by default;
    other layouts such as four pages can be chosen. It is turned on by hand:
    no folder or archive starts it by itself.

     ・ Two Pages [T] : Turns pages side by side on and off. The image chosen
        and the images after it in the list are shown.

     ・ Page Layout : Chooses the layout: at first "Two Pages (2 × 1)" and
        "Four Pages (2 × 2)", pages side by side × rows. The layout chosen is
        used in that window and in the windows opened next.

     ・ Right to Left (Manga) : On, the image chosen is on the right and the
        next one on its left. Off, left to right. Rows go from the top. A
        setting of the current layout.

     ・ First Page Alone : On, the first image of the list (the cover) is
        shown alone. A setting of the current layout.

     ・ Shift One Page [O] : Goes on by one page, to pair the pages the other
        way, for a book whose spreads do not match.

     ・ Edit Layouts... : Opens a window to edit the layouts: for each, its
        name, pages side by side (1 to 4), rows (1 to 3), right to left, first
        page alone; layouts can be added, removed and moved up and down.
        Changes are shown at once and kept in the settings. The name is shown
        in the menu and the status bar.

    The next image (a click, Space, Page Down) shows the next pages, the
    previous image (Page Up) the ones before. A click of the left button goes
    by the side clicked: in a book from right to left the left half goes on
    and the right half back (left to right, the other way). With the pointer
    on the image, that side shows where a click goes ("◀ Next", "Previous ▶").
    The pages are shown at the height of the first one without a gap. A wide
    image (a spread scanned as one) is shown alone, and the pages before it
    end there.

    While pages are shown side by side, Create Thumbnail, Crop and Edit Faces
    cannot be used (it is not the image of a page).

    A book (a folder or an archive) read with pages side by side is remembered
    with its last page and layout (~/.gimv/books, the 1000 most recent): when
    a tab of it is opened again, that page is chosen and shown in the preview
    with pages side by side (going on from there). Turning them off in the
    book forgets it. Pages side by side are for the tab (the book) they were
    turned on in only: an image opened from another tab, or from a list of
    dates, tags and so on, is shown alone; opening an image in the tab of the
    book again shows pages side by side again. Closing that tab turns them off
    (the book is still remembered). While pages are side by side, the pages of
    the next turn are read beforehand in a thread (the formats of GdkPixbuf;
    the images in an archive are extracted first).

    With "Auto resize to image size" of the image window, the window is sized
    for all the pages of the layout (four pages for 2 × 2), the cover shown
    alone too, and only when pages side by side are turned on, the layout is
    changed or another folder is shown: turning pages does not change the size
    of the window ([View | Fit to Image] sizes it again at any time).

    With pages side by side, the status bar shows "Two Pages 2-3 / 8" (the
    name of the layout and pages 2 to 3 of 8) or "Two Pages 6 alone / 8" (page
    6 shown alone) on its right; for the preview, the status bar of the
    thumbnail window. In the image window the Two Pages button of the toolbar
    turns it on and off too.

Fit to Image [I]
    Image window only. Resizes the image window to the size of the image

4.6. Tools

This menu exists only in the thumbnail window.

Clear All Caches
    Deletes all thumbnail caches of the format of "Cache type for saving" in
    [Preferences | Thumbnail Cache].

Missing Images...
    Opens the list of the images with comments (tags) that went missing, whose
    comments can be put on where they went or on another image, or deleted
    (2.6). Only with the image index.

Search Images...
    Opens the window to find images of the index by tags, people and a period
    (2.8). Only with the image index.

Find Duplicates...
    Looks for the duplicate images among all the images of the active tab (the
    selection does not matter) and opens the result window. One search sorts
    them into these kinds:

     ・ Identical: the same files (the same bytes).

     ・ Other Sizes: the same picture in other sizes (pixels): the same shape,
        none of the same size. Copies are included.

     ・ Same Pixels: the very same pixels, only the metadata (date taken,
        comments) or the format differs.

     ・ Saved Again: the same picture saved again in another quality, format
        or size (only the noise of JPEG differs).

     ・ Brightness, Colours: the same picture, the whole of it a little
        brighter, darker or of other colours.

     ・ Partly Different: a part differs (another face or clothes of a
        difference picture, writing, a mark).

     ・ Alike, Other Pictures: alike but other pictures (pages one after
        another, shots one after another).

    How similar is set by "Accuracy" in [Preferences | Search]. The ones alike
    of the same size are compared again at the end, small and at full size,
    and sorted from Same Pixels to Alike, Other Pictures (in a thread).

    On the left are the groups, under a heading of each kind that opens and
    folds with its arrow (or a double click). At first Identical, Other Sizes,
    Same Pixels and Saved Again are open, and Brightness, Colours, Partly
    Different and Alike, Other Pictures folded (they are usually not deleted).
    Each group shows the kind, the number of images, and how many are to
    delete (and their size). The images of the group selected are side by side
    on the right to compare: the size, the file size, the format, the date
    taken, how alike the first, the folder, and whether it has a comment. A
    click on a picture shows it in the thumbnail window (what it does is set
    in [Preferences | Search]).

    Each image is marked "Keep" or "Delete". In the Identical and Other Sizes
    groups the one with the most pixels (then the largest file, the oldest) is
    kept and the others are to delete, but in an Other Sizes group a copy
    found to be a smaller one only made larger shows "Looks like an enlarged
    copy" and is not the one kept (it is looked for in a thread after the
    groups are shown, and each group is ordered again when done; Keep and
    Delete chosen by hand stay); in the Same Pixels and Saved Again groups the
    one that seems best to keep comes first with "Suggested to keep" and why
    (the same pixels: the largest file, with the most metadata; saved again: a
    format keeping the pixels such as PNG, the most pixels, the highest JPEG
    quality), shown only: nothing is marked to delete. The cards show the JPEG
    quality and how each differs from the first (saved again, another size,
    brightness or colours, a part, another picture). In the groups of the
    other kinds all are kept. "Move to Trash..." at the top right moves the
    images to delete of the group shown, and only those, to the trash after
    asking (they can be put back from the trash): a group at a time, to be
    careful. The question names the files and says so when all of the group
    are to delete (then "Cancel" is the default) or some have comments. Then
    the next group is shown. With more than one group, "Move All Marked to
    Trash..." at the bottom moves those of all the groups at once (the groups
    with every image to delete are left out).

    Before they are moved, the images to delete are compared with the image
    kept again (Identical groups): a file changed since is not moved. When
    some of them have comments (tags) or bookmarks, "Move Them to the Kept
    Ones and Trash" can be chosen: a comment moves to the image kept when it
    has none, else its tags are added to those of it (a comment of tags only
    is then deleted); a bookmark moves when the image kept has none. With
    "Move to Trash Only" the comment files stay.

    When the file names mean something, "Trash and Leave Links" (Identical
    groups only) moves each file to the trash and puts a link to the image
    kept under its name: a hard link on the same file system (no space used,
    not broken when the image kept is moved), else a symbolic link (the
    absolute path of the image kept). The comments, tags and bookmarks stay
    with the name. When the link cannot be made, the file is not moved either.

    The window reads the pictures itself: the images the thumbnail view has
    not loaded are shown too. It can be used while it searches: the Identical
    groups come first, all of them at the end. The images in archives are not
    compared. How they are found and sorted: see "How duplicates are found".

Find Duplicates in the Index...
    Looks for the same files (Identical) among all the indexed images and
    opens the same result window: the same files in different folders are
    found too. The index has looked for them before, so nothing is read and
    they are shown at once. This needs "Look for the same files" in
    [Preferences | Index].

    The index reads only the images of the same size (bytes) as another one,
    after the rest: the first 64 KB are compared, and the whole files only
    when those are the same. The images of the same name and size (saved again
    in another folder) come first, so those are found at once. With many
    images the first time may take hours; meanwhile the status bar says
    "Index: same files n%", and the window shows what is found so far. Hard
    links to one file count as one. Other sizes and similar pictures are not
    looked for here (Find Duplicates on the images of a tab does that).

    Below a folder only: "Find Duplicates with the Folders in It..." of the
    directory view; the same files as an image: "Find the Same Files" of the
    thumbnail view.

Set as Wallpaper
    Makes the selected image the wallpaper of the desktop. "This Desktop" uses
    the command for the running desktop (environment variable
    XDG_CURRENT_DESKTOP). Below it are items for each desktop: Xfce, GNOME,
    KDE Plasma and others.

    Images other than JPEG and PNG, and images in archives, are converted to
    PNG in ~/.gimv/wallpaper/ and that file becomes the wallpaper. The items
    and commands can be changed with wallpaper_menu in ~/.gimv/gimvrc.

Rename... / File Names to UTF-8... / Copy Files To... / Move Files To... /
Link Files To... / Remove Files...
    The same as the items of the [Edit] menu.

Save Smaller...
    Saves the selected images smaller, as new files. The original files are
    not changed. Useful to make photos take less space.

    You can choose which of the height, the width or the longer side to keep
    at or below how many pixels (800 px of the height by default), the quality
    of JPEG and WebP, and what to add to the names ("_resized" by default:
    big_resized.jpg for big.jpg, in the same folder). When a file of the same
    name is already there, -1, -2, ... is added to the name; nothing is
    overwritten. The EXIF orientation is applied to the pixels.

    You can also choose whether to keep the shooting information (EXIF etc.),
    whether to leave out the location (GPS) then, and whether to copy the
    comments and tags. Images already smaller than the size are copied as they
    are. Images in formats gdk-pixbuf cannot write are saved as JPEG.

    The size and the file size of the first image after saving are estimated
    in the dialog. Saving runs in the background, so you can keep working;
    [Stop] stops the rest. When it is done, [Show the Saved Image] chooses the
    image saved.

Join Images...
    Joins the two or more selected images into one, saved as a new file. The
    images are not changed.

     ・ Images: the order they are joined in; ↑ ↓ move the image chosen.

     ・ Arrange: one below another, side by side, in a grid (with the number
        of columns).

     ・ Size: the width (the height side by side) made the one of the
        smallest, of the largest, or not changed (then centered, white
        around).

     ・ Look for overlaps: for the pieces of one photo that overlap where they
        meet, the end of an image and the start of the next most alike are
        found and put over each other (a little different JPEG too). A plain
        part (white) is not taken as an overlap.

     ・ Seam, Overlap: the overlap (px) of each seam can be put right with the
        slider or the number; "Seam" chooses which (1 and 2, 2 and 3, ...).
        Beside it, (found: n px) is the overlap found, or (none found).

     ・ How the seam is shown: in the whole image above, the seams are red
        dashed lines (the one chosen darker). Below, the seam chosen is shown
        near its own size: one below another, the end of the image before
        above and the start of the next below. Two pairs of red triangles at
        the sides: the first (upper, left) is where the next image begins, the
        second (lower, right) where the one before ends; between them they
        overlap (one pair with no overlap). The next image is shown from the
        first pair on, so they match when the picture goes on there without a
        step.

     ・ As the difference: the band where they overlap (between the triangles)
        is shown as the difference of the two images: black when they match,
        the outlines of things bright when they do not. Changing the number
        one by one to find where the band is darkest is the easy way to match
        them.

     ・ When no overlap is found: where they overlap only in a plain part (a
        sky, a white background), it may not be found (it looks the same
        anywhere). Then put the overlap in by hand, by something seen in both
        images (an edge, letters).

     ・ The quality (JPEG, WebP; 90 by default), keeping the information
        (EXIF, ...) of the first file, copying the comment and the tags given
        by hand of the first one.

    Saved next to the first image as "name_join.jpg" (in its format; JPEG when
    gdk-pixbuf cannot write it, PNG for the formats of gimv's own loaders,
    MAG, Pi, ...), never over another file (-1, -2, ... is added). The EXIF
    orientation is applied first. MAG, Pi and the like can be joined too (as
    they are shown: stretched to the shape of the pixels of their machine).
    Saved as PNG, the comments written in the files (the comment, the user
    name of MAG, ...) go into the comment of the PNG (under the name of each
    file when they differ). The images are read, the overlaps found and the
    image saved in threads. [Show the Saved Image] then chooses it in the
    thumbnail window.

7. Preferences
==============

This section describes the items of the preferences dialog.

7.1. Common

File Open Window
    The window a file is opened in when it is given on the command line or
    chosen with "OK" in the file open dialog.

    Where nothing like "Open in ... window" is specified, this setting decides
    the window.

Directory Open Window
    The window a directory given on the command line is opened in.

Archive Open Window
    The window an archive given on the command line is opened in.

Scan directories recursively
    Directories given on the command line are always read recursively.

    This is the same as the command line option -dR.

Follow symbolic links / Do not follow symbolic links
    Whether directories that symbolic links point to are read when reading
    recursively.

Interpolation type for scaling
    The interpolation used when an image is scaled. One of these four:

     ・ Nearest: nearest neighbor. The fastest, but the result is coarse.

     ・ Tiles: like Nearest when enlarging; averages the pixels when reducing.

     ・ Bilinear: bilinear interpolation. A good balance of speed and quality.

     ・ Hyperbolic: the best quality, but slow.

Color scheme
    The colors of the windows. One of these three; the change is used at once
    (Apply or OK). This item was added in the GTK 4 version (Desktop theme by
    default).

     ・ Desktop theme: the theme chosen on the desktop (gtk-theme-name of GTK;
        on X11 the XSETTINGS value Net/ThemeName). GTK 4 cannot read themes
        without a gtk-4.0 directory (themes for GTK 2/3) and shows the light
        Adwaita instead. If the name of such a theme contains "dark"
        (Greybird-dark, for example), the dark Adwaita is used.

     ・ Light: light colors. If the name of the theme ends with "-dark", the
        theme of the name without it is used, or Adwaita if GTK 4 cannot read
        that theme.

     ・ Dark: dark colors. If the theme has no dark version (gtk-dark.css),
        the dark Adwaita is used.

    If the environment variable GTK_THEME is set, GTK uses that theme and this
    item has no effect. The icons of GImageView drawn only with black lines
    (Zoom, Show/Hide dotfiles, ...) are drawn with light lines in dark colors.

Use icons of the desktop icon theme for buttons
    Toolbar and other buttons use icons of the desktop icon theme (Adwaita,
    Papirus, ...). Buttons with no matching icon in the theme, and the icons
    of the directory tree, use the icons of GImageView. Windows opened after
    the change use it. This item was added in the GTK 4 version (on by
    default).

    To use your own icons, put files named after the icons (back.png,
    zoom_in.svg, refresh.xpm, ...; PNG, SVG and XPM can be used) in ~/.gimv/
    icons/<name>/ and write that name as iconset= in ~/.gimv/gimvrc. These
    icons take precedence over the icons of the theme.

Always show the scrollbars
    Shows the scrollbars of the lists and other views all the time. Off: as
    GTK 4 does by default, they are shown over the contents only while the
    pointer is near them. Added in the GTK 4 port (on by default).

Open thumbnail window
    Whether a thumbnail window is always opened when GImageView starts.

Ignore directories
    Directories given as arguments are ignored.

No warning
    Suppresses the warning messages shown when started from the command line.

Show splash window
    Whether the splash window (logo image) is shown at startup. This item was
    added in the GTK 4 version.

    for in a thread, only for those on the screen, and kept in the thumbnail
    cache when one is written. Of a zip, cbz, LHA or uncompressed tar the list

    after 3 seconds or 256 MB unpacked the cover is the best so far (of a big

7.8. Index

The image index (2.6) and face recognition (2.7). Only in a build with SQLite.
Changes take effect after "Apply" or "OK", with the indexer started again.

Index
    "Index images by date" and "Directories to index": the images below these
    directories are indexed. With "Look for the same files" on, the images of
    the same size as another one are read after the rest, to find the same
    files (Find Duplicates in the Index). The first time may take hours; it
    goes on at the next start when GImageView is quit in the middle.

Index | New Images
    Whether new images are notified on the desktop, how long they are gathered
    into one notification, the interval between two notifications, how long
    one is shown, and the folders not to notify. Where the notifications
    appear is set in the desktop's notification settings.

Index | Automatic Tags
    The kinds of automatic tags (folder name, camera, shape, the keywords of
    other programs) and the folder names not made tags ("*" matches any
    letters, "?" one; capitals and small letters are the same). Turning the
    camera, the shape or the keywords on reads every image again, which takes
    long with many images.

Index | Faces
    The folders to find faces in (inside the directories to index), and where
    the model files are. When they are not found, where to put them and where
    to get them (URLs) are shown. Only with face recognition.

    The model files are these two, put in ~/.local/share/gimageview/models
    (with these names; the quantized "_int8" and "_int8bq" ones next to them
    are not used):

     ・ face_detection_yunet_2023mar.onnx (finding faces, about 230 KB)

     ・ face_recognition_sface_2021dec.onnx (comparing faces, about 39 MB)

    They come from the OpenCV Zoo:

     ・ GitHub (the URLs shown on the preferences page):
        https://github.com/opencv/opencv_zoo/raw/main/models/
        face_detection_yunet/face_detection_yunet_2023mar.onnx
        https://github.com/opencv/opencv_zoo/raw/main/models/
        face_recognition_sface/face_recognition_sface_2021dec.onnx

     ・ Hugging Face (when GitHub does not give them; the README on GitHub
        says the OpenCV Zoo moved there):
        https://huggingface.co/opencv/face_detection_yunet/resolve/main/
        face_detection_yunet_2023mar.onnx
        https://huggingface.co/opencv/face_recognition_sface/resolve/main/
        face_recognition_sface_2021dec.onnx

    GImageView checks what is in the model files (SHA-256): a broken download,
    or another file (another version) of the same name, is not used; then this
    page and the tooltip of the status bar tell which file to download again
    and its URL. The index records the model the features of the faces were
    made with: when a new version of GImageView has another model, the
    features are made again at the place of each face found (the faces, their
    names and "not this person" stay; the status bar shows how far it is; the
    faces of an image that cannot be read any more are looked for again when
    it can be).

Index | Missing Images
    How many logs of the images with comments (tags) that went missing are
    kept (0: none).

9. GImageView FAQ
=================

9.1. Getting, Installing and Starting

There is no configure
    The GTK 4 version is built with Meson, not with configure (autoconf /
    automake). For the procedure, see Installation.

I want to start the GImageView thumbnail window alone
      $ gimv -w

    Start it like this. If [Edit | Options] - [Common | Startup | Open
    thumbnail window] is checked, the -w argument is not needed.

      $ gimv

    alone starts it. After that, it works normally when you open some
    directory or file.

    When registering it in a launcher, specifying just gimv is OK.

9.2. Operation and Settings

I want to change the defined key bindings
    Use [Edit | Keyboard Shortcuts...]. Click the key of a row and press the
    new key: it works at once and is kept (4).

    The files can also be edited. ~/.gimv/keyconf has the keys of the right
    button menu, completion, the navigator and the display modes; it takes
    effect from the next start.

    Menu shortcut keys can be changed in ~/.gimv/keyaccelrc. A line for every
    menu item is written out on exit, so remove the ";" at the beginning of
    the line you want to change and rewrite the key. For example, to make
    [File | Open] (Ctrl + F by default) of the thumbnail window F3, do the
    following. It takes effect from the next start.

      (gtk_accel_path "<ThumbWinMainMenu>/File/Open..." "F3")

    If you change the key bindings, only you know how it will behave. Please
    do this at your own risk.

9.3. Thumbnail Window

What is shown in the status bar?
    From the left: the full path of the focused image ("~" for the home
    directory), its position in the tab ("10 / 16") and its file size. With
    several images selected, their number and their total size ("5 selected
    812 kB"). At the right end, the state of the image index ("Index: 28
    images" and so on; the details are in the tooltip) and the "Notices"
    button (2.3).

Where are the numbers of files, the total size and the tab number of the older
versions?
    In the GTK 4 version, the status bar shows only the image in hand; the
    numbers of files, the total sizes and the tab numbers of all the tabs
    ("**/** files", "**/** kB", "**/** page") are no longer shown. The number
    of images in the tab is the second number of the position ("10 / 16"). A
    right click on the tabs shows the list of the open tabs.

How do I use the input entry on the right of the toolbar?
    Try specifying various absolute paths. The directory tree (if you are
    showing it...) should do something interesting.

    It is very hard to explain, but this is where you specify a new (or
    existing) tab in a command-line-like way. Even when the directory view is
    not shown, you can open a new tab or move to an existing tab without
    relying on the file open dialog.

    In this input entry, completion with the TAB key works. Press TAB freely,
    as you would in bash, tcsh or zsh. If there is only one candidate, it is
    completed automatically. If there are many candidates, they are listed
    below the input entry. In this input entry, the shorthand "~/" for the
    user's home directory is ignored. Always specify an absolute path.

    Also, individual files cannot be specified here. Input completion does not
    work for them either. If you want to open a single image in a separate
    window, first show that directory as thumbnails, and open it from there by
    middle-button click, left double-click or similar.

    When the focus has moved to the input entry, use one of the following
    methods to move the focus back (to enable keyboard shortcuts).

     1. In the directory view, left-click some directory to "select" it.

     2. In the thumbnail view, click (select / unselect) some image.

     3. Click a tab to move to another tab.

     4. Left-click (or Shift + left-click) in the preview window to change the
        display.

     5. Press the Esc key.

    Moving the focus from GImageView to another window (for example rxvt) does
    not switch the focus within GImageView. Note that the focus does not leave
    the input entry unless you do one of the operations described above.

9.4. Tabs

How do I show a list of the currently open tabs?
    Right-click on the tab area. A list of the currently open tabs is shown.
    You can also move to any tab.

Stopping the full path display on tabs
    Uncheck "Show full path" in [Preferences | Thumbnail Window | Tab]. Only
    the directory name will be shown on the tab. The full path of a tab is
    then shown in its tooltip.

What is a collection tab?
    You can make one from [File | New Collection]. Or select images in any tab
    and drag and drop them somewhere suitable.

    The DnD menu appeared, right?

    There, choose [Open in New Tab]. The dragged image (all of them, if there
    are several) is opened in a new tab (named Collection).

    To add new images to a collection tab you made, there are the following
    methods.

     1. DnD onto the tab of the collection tab

     2. DnD onto the thumbnail view in the collection tab (in this case, from
        another application or from a second or later gimv)

     3. With the collection page open, select files from the file open dialog
        (the button at the left end of the toolbar), and use "Thumbnails of
        the selected files"

    For DnD onto a collection page, the DnD menu is not shown and the files
    are added immediately.

    After collecting, move or copy them to any directory. The collected images
    are treated as one group. Rather than Ctrl-clicking the images one by one,
    gathering them in a collection tab first and then doing file operations on
    them should make organizing images more efficient.

9.5. Directory View

How to show in the tree a directory added from the console
    Do [Refresh Tree] on the parent directory of the added directory in the
    tree view, and it is shown. If you use [Make Directory...] from the right-
    click menu of the tree view, it is shown immediately, so adding
    directories this way is easier.

About "Load Thumbnails Recursively" in the right-click menu of the directory
view
    Loads everything under that directory recursively.

    That is, it expands everything under that directory and makes a thumbnail
    tab for each directory. It is very convenient when you want to expand only
    a certain place. The tree is also expanded properly.

    If you load recursively from a high-level directory (such as directly
    under ~/) and the directory loading does not stop, stop it with the stop
    button in the toolbar, or skip that directory with the skip button.

What are "." and ".." in the directory view?
    Here is an example.

      /home/~
          + cg
             + .
             + ..
             + desktop
             + favorite
             |    + .   (1)
             |    + ..  (2)
             |    + web
             |    + download
             + tmp

    Suppose it looks like this. If you double-click "." at (1),

      /home/~
         + web
         + download

    that directory becomes the root directory. This means the same as [Go
    Here] in the right-click menu of the directory view.

    And if you double-click ".." at (2),

      /home/~
         + desktop
         + favorite
         |    + web
         |    + dl
         + tmp

    its parent directory becomes the root.

How to make the tree expand automatically and the view scroll up and down
automatically during DnD from a tab window to the directory view
    These settings ([Auto scroll] and [Enable auto expand directory tree])
    exist only in the GTK+ 1.2 version, and not in the GTK+ 2 version and
    later (including the GTK 4 version). If the destination directory is
    collapsed, expand it beforehand.

Fixing the list view mode at startup and for new tabs
    You can specify it in [Preferences | Thumbnail Window | Thumbnail View |
    Default display mode]. However, for this to take effect, "Save window
    state on exit" must be unchecked (not saved).

The thumbnails look strangely bad
    A thumbnail cache of a different size may have been loaded. For now, run
    Update Thumbnail.

Selecting / unselecting all images at once
    It is in the [Edit] menu. It is not in the mouse menu. Shortcuts are
    assigned (Ctrl + A [N]), so if you use it often, it is better to use
    those.

Clicking (toggling) a thumbnail does not change its color
    The color of a selection depends on the current gtk theme. The color
    probably does not change because of the color settings of the theme. Try
    another theme.

    Leaves the display of images in a separate window to another program.

    Set the external programs in [Preferences | External Program]. You can
    also register your own scripts and so on.

10. Tips
========

Making drawing in the image view faster
    Check [Preferences | Image Window | Image | Keep the original image in
    memory]. For the image windows open only, [File | Memory Buffer] (Ctrl +
    B) turns it on and off.

    When an image has been shown, GImageView drops the original image (the
    pixels read). So when the zoom is changed or the image is rotated or
    flipped, the original image is read from the file again. Kept in memory,
    it is not read again, which is faster the larger the image is.

    When an image is opened first, it is read from the file whatever the
    setting, so this option does not matter there. Keeping the original image
    uses width × height × 3 or 4 bytes of memory more per image (about 40 MB
    for a photo of 12 megapixels). For this reason the default setting is OFF.
    Animations, movies and audio are kept whatever the setting.

Changing the thumbnail size temporarily
    Change the thumbnail size in the toolbar (press Enter when typing a
    number), then use [Edit | Reload Cache] (Shift + R) or [Edit | Update All
    Thumbnails] (Ctrl + R) to apply it.

    If you use "Reload Cache", the cached images are enlarged (or reduced) to
    the new thumbnail size and displayed. Reducing is fine, but when
    enlarging, the dots become coarse. To avoid this, use "Update All
    Thumbnails". The cache is recreated at the new size, so the dots do not
    become coarse.

    The thumbnail size belongs to each tab: switching tabs shows the size of
    that tab. A new window or an empty tab goes back to [Preferences |
    Thumbnail Window | Thumbnail View | Thumbnail Size]. With "Save window
    state on exit" in [Preferences | Thumbnail Window] on (the default), the
    value in the toolbar at exit is saved there and is the size from then on.

Differences between [Refresh List], [Reload Cache] and [Update All Thumbnails]
    Refresh List (Shift + Ctrl + R)
        Updates only the differences between the information on disk and in
        memory. It only updates the file list and does not resize the
        thumbnails.

    Reload Cache (Shift + R)
        Discards all information and reads all information from disk again. At
        this time, if a cache exists it is read from the cache, and if not,
        the thumbnail is created from the original image. If a cache exists,
        only the thumbnail is resized.

        Because it is a resize and not a re-creation, if the saved cache is
        smaller than the specified size, the thumbnail is simply enlarged and
        the image looks bad.

    Update All Thumbnails (Ctrl + R)
        Discards all information and reads all information from disk again.
        All thumbnails are re-created from the original images. When the
        displayed thumbnail size has been changed, this is probably the best
        one to use. The part on screen is made first and the rest in the
        background, keeping the scroll position. The progress (n/N) is shown
        while it runs, and the stop button in the toolbar stops it.

About custom layouts
    [View | Layout] places the views of the thumbnail window (directory view,
    thumbnail view, preview) as Layout 0 to 4 (Ctrl + 0 to 4). Layout 0 is the
    default. These layouts are fixed and cannot be changed.

    For other arrangements there is "Custom". The layout becomes "Custom" by
    itself with these:

     ・ [View | Layout | Window Composition] chooses how the window is split
        (the panes horizontal or vertical, and how they are put together).

     ・ Dragging a view and dropping it on another one swaps the two. The
        parts to drag are the tabs of the thumbnail view, the toolbar of the
        directory view and the tabs of the preview (Preview, Data, Note).

    The custom layout is saved as these six items of ~/.gimv/gimvrc, which can
    also be edited by hand while gimv is not running:

     ・ thumbwin_pane1_horizontal (whether pane1 is split horizontally or
        vertically)

     ・ thumbwin_pane2_horizontal (the same for pane2)

     ・ thumbwin_pane2_attach_1 (whether pane2 is attached to child1 or child2
        of pane1)

     ・ thumbwin_widget[0] (the widget attached to the other side of pane1: 1
        is the directory view, 2 the thumbnails, 3 the preview)

     ・ thumbwin_widget[1] (child1 of pane2)

     ・ thumbwin_widget[2] (child2 of pane2)

    Layouts 0 to 4 are these six values set in advance.

How duplicates are found
    [Tools | Find Duplicates...] goes through the images of the active tab in
    the steps below and sorts what it finds into kinds of groups: Identical,
    Other Sizes, and the kinds of the similar ones (Same Pixels, Saved Again,
    Brightness, Colours, Partly Different, Alike, Other Pictures). It searches
    in another thread: the window can be used meanwhile.

     1. The same files: the md5 is computed only for the files of the same
        size (in bytes); the same md5 means the same bytes. A file whose size
        no other has is not read.

     2. The pictures read small: one of each set of the same files is read
        small (about 128 dots), turned as its EXIF orientation says, squeezed
        into a 32x32 frame whatever its shape, and the R/G/B means of each
        part are taken (some programs call it a "fingerprint"). The thumbnails
        are not used: the images the thumbnail view has not loaded yet are
        compared too.

     3. The pictures compared: the R/G/B differences of two fingerprints are
        averaged (0 to 1.0); 1.0 minus that is how alike they are. At or above
        the value of the preferences they match. Images whose total brightness
        is too far apart cannot match and are not compared.

     4. The kinds: a group of the same files only is Identical. When the
        images that match all have the same shape and no two of them have the
        same size, it is Other Sizes (copies included); else they are similar
        ones.

     5. How the similar ones differ: the images of a similar group are
        compared about 256 dots small (the mean differences of parts 8 dots
        square): small all over is the same picture, a few parts (under 5%)
        far off is Partly Different, else Alike, Other Pictures. A shift of
        the brightness or colours of the whole is taken out first. The same
        picture is compared at full size with the first (the one that seems
        best to keep): no difference is Same Pixels, the means of the colours
        shifted Brightness, Colours, about the noise of JPEG Saved Again. A
        small difference seen only at full size (a signature) is Partly
        Different. When there are sets of the same picture, each is a group of
        its own, and their firsts make the groups of Partly Different and
        Alike, Other Pictures. The limits follow a survey of 2.4 million
        pictures.

    How alike they must be is "Accuracy" in [Preferences | Search] (0.97 by
    default: 97% or more alike match). A lower value puts more images among
    the similar ones.

    In the Identical and Other Sizes groups the one with the most pixels (then
    the largest file, the oldest, the shortest path) is marked Keep and the
    others Delete. In an Other Sizes group, an image twice as large or more is
    checked for being a smaller one only made larger: then it shows "Looks
    like an enlarged copy" and is not the one kept (see "How an enlarged copy
    is told" below). In the Same Pixels and Saved Again groups the one that
    seems best to keep (the most metadata, a format keeping the pixels such as
    PNG, the most pixels, the highest JPEG quality) comes first with
    "Suggested to keep" and why, but nothing is marked Delete. The JPEG
    quality is guessed from which quality of libjpeg the quantization table of
    the file is nearest to. The groups of the other kinds may be other
    pictures: all are marked Keep. Which to keep is for a person to check and
    decide. "Move to Trash..." moves those to delete of the group shown, "Move
    All Marked to Trash..." those of all the groups at once; they are compared
    with the image kept again first.

    Because of how it works, it may not do what one expects in these cases.

     1. Images whose color balance or brightness has changed as a whole match
        less (every part differs evenly).

     2. Images with a part (top/bottom/right/left) cut off match less (parts
        that do not correspond are compared). Rotated or mirrored images do
        not match.

     3. A copy only blown up is not told when it is less than twice as large,
        when the picture has little detail, or when it is a JPEG saved at a
        low quality (about 70 or less): it has more pixels and is marked Keep.
        One blown up by AI (waifu2x, ...) has detail made up and may not be
        told.

     4. Images gimv shows but gdk-pixbuf cannot read are looked at for
        Identical only. The images in archives are not compared.

    How an enlarged copy is told: an ordinary enlarging (nearest, bilinear,
    bicubic, Lanczos, of any program) makes each pixel of the large image a
    weighted sum of the pixels around its place in the small one. The best
    weights to predict the large image from the small one are fitted on half
    of the pixels, and the error of the prediction is measured on the other
    half: an enlarged copy is predicted down to about its JPEG noise, a
    picture really larger keeps the detail the small one does not have. The
    error is compared with the error of predicting the small image from itself
    made smaller by as much (photographs have alike detail at all scales:
    about the same for a real one, less than 0.35 times for an enlarged copy).
    With the test pictures, about nine in ten of the copies enlarged twice
    were told, and no real one was taken for a copy; it takes about 0.2
    seconds a pair (12 million pixels).

    To find the same files across folders, not only in the active tab, use
    [Tools | Find Duplicates in the Index...] (the index looks for them in the
    background): see "Find Duplicates in the Index...".
