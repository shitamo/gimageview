9. Tips

Making the thumbnail view finish drawing faster

gimv loads thumbnails at once in batches of the number specified in [Preferences | Thumbnail Window | GUI redraw interval while loading].

On a machine that draws slowly, increasing this value reduces the number of thumbnail updates (screen updates), which makes it somewhat faster. However, the larger the value, the less often the screen is updated and the longer nothing is shown, so 5 to 15 seems appropriate.

Making the image view finish drawing faster 1

In [Preferences | Image Window | Show/Hide], either check all items or uncheck all items.

GImageView creates the window once and then removes the bars that are not checked. If "none" are checked, none of them are created, and conversely, if "all are checked", all of them are created. Skipping this makes it faster by the amount of the "remove" operation. This is very effective when opening large images (larger than the screen resolution).

Making the image view finish drawing faster 2

Check [Preferences | Image Window | Image | Fit to the window size when opening a file].

Regardless of the user's settings, GImageView opens the image at the size specified in [Image Window | Window | Initial window size], and then resizes it to the original size of the image. Checking this option skips that resize, so it becomes faster by that amount of time. However, this is effective only when the image being opened is larger than the specified initial size.

Note that with this setting, the only way to "display at the image size" in the image view is to click [No Zoom] to resize the image to its actual size, and then use "Fit Window Size to Image".

Making the image view finish drawing faster 3

Uncheck [Preferences | Image Window | Image | Auto resize to image size].

With this, images smaller than the initial window size are not resized either. Combined with the setting above, images are opened at the specified size regardless of their original size, which makes it faster by the amount of the resize.

Note that with this setting, the only way to "display at the image size" in the image view is to click [No Zoom] to resize the image to its actual size, and then use "Fit Window Size to Image".

Making drawing in the image view faster

Check [Preferences | Image Window | Image | Keep the original image in memory].

When a displayed image is resized or rotated, GImageView re-renders the "original image" and displays it again. If you choose to "keep the original image in memory", the "original image" is read from memory when rendering, and the drawing speed during rendering is greatly improved compared with reading it from disk every time (when unchecked).

When an image is opened for the very first time, it is read from disk whatever the setting, so this option does not matter there. Keeping images in memory uses an extra amount of memory of somewhat less than 1MB, and sometimes several MB or more, per image, so on a system with little memory, opening only a few images may use up the memory. For this reason the default setting is OFF.

This is obvious at a glance if you check the memory consumption of the GImageView process with the buffer ON and with the buffer OFF, using top or similar. Incidentally, similar programs such as GQview, gThumb and G-ThumB always have what GImageView calls the "buffer" ON, so the difference in memory consumption should be noticeable when several or more images are opened at the same time.

This is also related to the low memory consumption that GImageView claims.

Changing the thumbnail size temporarily

Change the value in the toolbar and press Return, then use [Edit | Reload Cache] (Shift + R) or [Update All Thumbnails] (Ctrl + R or the mouse menu) to apply it.

If you use "Reload Cache", the cached images are enlarged (or reduced) to the new thumbnail size and displayed. Reducing is fine, but when enlarging, the dots become coarse. To avoid this, use "Update All Thumbnails". The cache is recreated at the new size, so the dots do not become coarse.

The setting made in the toolbar is not applied to new windows or new tabs (it is not saved). The value changed here is valid only in that tab. To change it permanently, change the value of [Preferences | Thumbnail Window | Thumbnail View | Thumbnail Size], or enable "Save window state on exit".

Differences between [Refresh List], [Reload Cache] and [Update All Thumbnails]
Refresh List (R)

Updates only the differences between the information on disk and in memory. It only updates the file list and does not resize the thumbnails.

Reload Cache (Shift + R)

Discards all information and reads all information from disk again. At this time, if a cache exists it is read from the cache, and if not, the thumbnail is created from the original image. If a cache exists, only the thumbnail is resized.

Because it is a resize and not a re-creation, if the saved cache is smaller than the specified size, the thumbnail is simply enlarged and the image looks bad.

Update All Thumbnails (Ctrl + R)

Discards all information and reads all information from disk again. All thumbnails are re-created from the original images. When the displayed thumbnail size has been changed, this is probably the best one to use.

About custom layouts

By specifying [View | Layout], you can change the position of each pane of the GImageView thumbnail window. Layout 0 is the default, and layouts up to Layout 4 are provided as standard.

Besides these layouts, you can also make any pane arrangement as a custom layout.

Currently (version 0.1.2), custom settings cannot be made from a GUI or CUI. To make custom settings, you need to edit ~/.gimv/gimvrc directly. A settings screen or a settings method will probably be properly built in in the future. Until then, please do this at your own risk.

The items to edit are the following 6.

  • thumbwin_pane1_horizontal (whether pane1 is split horizontally or vertically)

  • thumbwin_pane2_horizontal (the same for pane2)

  • thumbwin_pane2_attach_1 (whether pane2 is attached to child1 or child2 of pane1)

  • thumbwin_widget [0] (the widget attached to the other side of pane1. 1 is the directory view, 2 the thumbnails, 3 the preview)

  • thumbwin_widget [1] (child1 of pane2)

  • thumbwin_widget [2] (child2 of pane2)

With Custom, the values set here are used. For Layouts 0 to 4, these 6 values are preset. They cannot be changed.

Custom layouts and window composition

Simply put, "a layout is something that can be customized freely", and "a window composition is a predefined one".

At present, the layout can be changed freely with "Window Composition" or with "DnD of the toolbar of the tab or directory view", and when these changes are made, the "layout" automatically becomes "Custom".

For now the "layouts" are fixed to 5 kinds (excluding "Custom"), but eventually it is said that you will be able to register as many of your own preferred arrangements as you like as "layouts". The interface under consideration is (adding an item "Save Layout" to the layout menu, so that a name can be given when saving a layout).

Similar image search

The similar image search algorithm of GImageView is as follows.

  1. Regardless of the size/aspect ratio of the image, every image is squeezed into a 32x32 dot frame

  2. The R/G/B differences of each pixel are accumulated and averaged (0 to 1.0)

  3. If the difference is below the threshold, the images are judged to "match"

This threshold can be set in "Search" in the preferences, but it is actually set as a similarity (1.0 - difference). If the value is at or above this, the images are judged to match (a percentage might have been better).

Also, for the 32x32 image data (some programs seem to call it a "fingerprint" or similar), the thumbnails are actually used for speed. For this reason it does not work correctly if thumbnails have not been created.

Because of this implementation, images that look very similar to a human at first glance may actually be judged as "not matching". This happens in the following cases.

  1. When the color balance is shifted as a whole (every pixel is uniformly judged to "have a difference")

  2. When the images are almost the same, but part of the image (top/bottom/right/left) has been cut off (pixels that do not correspond are compared)
